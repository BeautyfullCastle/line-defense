# 라인 디펜스 (Line Defense) — 게임 기획서 v1.0

> 원본 기획(`로드 디펜스`, `밸런스`, `장기 로드맵` 시트)을 바탕으로 작성한 웹 게임 기획서 및 구현 사양.
> 수치의 단일 원본은 `src/balance.js`이며, 이 문서의 표와 1:1로 대응한다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 물류 라우팅 + 타워 디펜스 |
| 레퍼런스 | 《Mini Metro》의 선 잇기/네트워크 관리 + 전선 방어 |
| 플랫폼 | 웹 (데스크톱 브라우저) |
| 프레임워크 | **의존성 없는 Vanilla JS (ES Modules) + Canvas 2D** |
| MVP 목표 | "생산지→요새를 선으로 잇고, 마차 보급으로 웨이브를 막는다"는 핵심 루프 검증 |

### 왜 Vanilla JS + Canvas 인가
- 이 게임의 연산은 **노드 수십 개 + 적 100여 마리의 좌표 갱신**이 전부다. React 같은 상태 기반 UI 프레임워크는 매 프레임 리렌더가 오히려 병목이 되고, Unity/Phaser는 이 규모에 비해 런타임이 과하다.
- 빌드 스텝이 없어 `index.html`을 정적 서버에 올리기만 하면 동작한다. 수정 → 새로고침의 반복 주기가 가장 짧다.
- 밸런스 수치가 단일 JS 객체에 모여 있어 **치트 메뉴가 런타임에 직접 조작**할 수 있다. 밸런싱 도구로서 가장 실용적이다.

### 핵심 루프
```
웨이브 준비(30s) → 노선 설계/보급 → 웨이브 교전 → 클리어 보상(코인/허가권)
   → 새 요새·새 생산지 추가 → 물류망 확장 → 반복
```
플레이어를 압박하는 것은 적의 강함이 아니라 **물류 처리량의 한계**다. 요새가 늘어나는 속도를 보급망 확장이 따라잡지 못하면 무너진다.

## 2. 질문에 대한 설계 결론

### Q1. 창고 & 마굿간은 내가 원하는 위치에 생성하는 건가?
**예. 허가권을 소모해 맵 위 원하는 좌표에 자유 배치한다.**

- 생산지와 요새는 **랜덤/자동 생성**(플레이어가 위치를 못 고름), 창고와 마굿간은 **플레이어가 위치를 지정**한다. 이 비대칭이 이 게임의 핵심 의사결정이다. 주어진 지형(랜덤 생산지)을 읽고 물류 허브를 어디에 놓을지가 실력이 된다.
- 제약은 **방어선 안쪽일 것**과 **다른 건물과 최소 62px 이상 거리**뿐이다. 노선 위에 있어야 한다는 제약은 두지 않는다 — 먼저 짓고 나중에 노선을 잇는 순서를 허용해야 설계 자유도가 산다.
- 건설 모드에서 마우스를 올리면 배치 가능 여부가 초록/빨강 고스트로 표시된다.

### Q2. 코인은 어떻게 얻는가?
**4가지 획득처를 둔다. 전투 보상 + 물류 효율 보상의 이원 구조.**

| 획득처 | 계산식 | 의도 |
|---|---|---|
| 몬스터 처치 | 몬스터별 1~3 코인 | 잘 막을수록 이득. 소액이지만 상시 유입 |
| 웨이브 클리어 | `25 + 10 × 웨이브` | 진행에 따른 기본 성장 재원 |
| 성벽 보존 보너스 | `30 × (요새 평균 체력 비율)` | 아슬아슬하게 막는 것보다 **여유 있게 막는 것**을 보상 |
| 잉여 자원 판매 | 창고 자원 1개당 2 코인 | 과잉 생산된 자원을 코인으로 전환. 물류 최적화의 출구 |

**코인 사용처**: 요새 강화(최우선) · 마차 증차 · 창고 확장 · 상위 마차 업그레이드.

> **설계 의도**: 코인은 "전투를 잘해서" 버는 돈이 아니라 **"물류를 잘 짜서" 버는 돈**이어야 한다. 그래서 성벽 보존 보너스와 잉여 자원 판매의 비중을 크게 잡았다. 보급이 넉넉해야 성벽이 안 깎이고, 넉넉해야 팔 잉여가 생긴다.

### Q3. 중/대형 창고는 건설 허가권 + 코인인가?
**신축이냐 확장이냐로 나눈다.**

| 경로 | 비용 | 비고 |
|---|---|---|
| 소형 창고 신축 | 창고 건설 허가권 ×1 | 허가권만으로 가능 |
| 중형 창고 **신축** | 허가권 ×1 + 코인 50 | 빈 땅에 바로 중형을 세우는 경우 |
| 대형 창고 **신축** | 허가권 ×1 + 코인 100 | |
| 소형 → 중형 **확장** | 코인 50 (허가권 불필요) | 이미 지은 창고를 키우는 경우 |
| 소형/중형 → 대형 **확장** | 코인 100 (허가권 불필요) | |

> **결론과 근거**: 허가권은 **"부지를 하나 더 점유할 권리"**, 코인은 **"그 부지의 규모"**를 의미하도록 개념을 분리했다. 이렇게 하면 허가권이 부족한 초반에는 기존 창고를 코인으로 키우는 선택지가 생기고, 허가권이 남는 후반에는 신규 거점을 늘리는 선택지가 생긴다. 두 재화가 서로를 대체하지 않고 각자의 역할을 갖는다.

### Q4. 짐칸은 소모되는 재화 없이 붙일 수 있는가?
**그렇다. 짐칸 부착·재배치는 완전 무료다. 비용은 재화가 아니라 "속도"로 지불한다.**

- 마차 종류별 **권장 짐칸**까지는 페널티 없이 자유롭게 배분한다. (식량칸/무기칸/석재칸을 몇 칸씩 둘지)
- **최대 짐칸 = 권장 짐칸 × 2**까지 초과 부착할 수 있고, 초과분에 비례해 이동 속도가 선형으로 감소한다.
- 감속 공식: 최대 짐칸까지 꽉 채우면 원본 표의 "권장 짐칸 초과 사용 시 이동 속도 감소" 값이 전부 적용된다 (= 기본 속도의 정확히 절반).

```
초과분 t = (현재 짐칸 − 권장 짐칸) / 권장 짐칸
이동 속도 = 기본 속도 − 감소치 × t     (하한 1)
```

| 마차 | 권장 | 최대 | 기본 속도 | 최대 적재 시 속도 |
|---|---|---|---|---|
| 기본 마차 | 10 | 20 | 4 | 2 |
| 스피드 마차 | 6 | 12 | 8 | 4 |
| 중형 마차 | 20 | 40 | 4 | 3 |
| 강화 스피드 | 12 | 24 | 8 | 6 |

> **설계 의도**: 짐칸에 돈을 매기면 "돈 없어서 못 나른다"는 이중 잠금이 된다. 대신 무료로 풀고 **적재량 ↔ 회전율**의 트레이드오프만 남기면, 플레이어는 매 노선마다 "많이 한 번에 vs 조금씩 자주"를 고민하게 된다. 이게 훨씬 재미있는 결정이다. 참고로 중형 마차는 감소치가 1로 가장 완만해서 대량 수송에 유리하다 — 코인 100의 값어치가 여기서 나온다.

### Q5. 요새의 식량/무기 최대 적재 수량, 그리고 공속 감소치 공식
**최대 적재량: 식량 40 / 무기 30 / 석재 20.**

수치 근거 — 생산지 1개의 산출량은 농경지 0.2/s, 대장간 0.1/s, 채석장 0.1/s다. 요새 1기의 소모는 식량 0.1/s(상시) + 무기 0.125/s(전투 중)다. 즉 **요새 1기를 온전히 굴리려면 농경지 1곳 + 대장간 1.5곳 규모의 보급망**이 필요하다. 적재량은 "약 5분치 비축"이 되도록 잡아, 웨이브 1회를 버틸 완충은 되지만 방치하면 반드시 바닥나는 크기로 설정했다.

**공속 감소치 = {식량 최대 적재량} / {기본 공속} 인가? → 아니다.**

그 공식은 단위가 맞지 않는다. `적재량 / 공속`은 [개] / [초] = 초당 개수가 되어 **시간 단위**가 나오는데, 우리가 필요한 건 공격 간격에 곱할 **무차원 계수**다. 또 그 식은 적재량이 커질수록 감소치가 커져서 "창고를 키웠더니 더 느려지는" 역전이 생긴다.

대신 **재고 비율 기반의 구간 선형 계수**를 쓴다.

```
재고비율 r = 현재 재고 / 최대 적재량

           ┌ 0                                    (r = 0,   재고 고갈 → 공격 불가)
계수 F(r) = ┤ floor + (1 − floor) × (r / safe)     (0 < r < safe)
           └ 1                                    (r ≥ safe)

  safe  = 0.30   (최대 적재량의 30% 이상이면 100% 성능)
  floor = 0.40   (재고가 바닥 직전이어도 최소 40%는 유지)

실제 공격 간격 = 기본 공격 간격 ÷ F(식량비율)      ← 식량이 공격 "속도"를 결정
실제 공격력    = 기본 공격력   × F(무기비율)       ← 무기가 공격 "력"을 결정
식량·무기 중 하나라도 0이면 공격 불가              ← 원본 기획 그대로
```

| 재고 비율 | 계수 | 공격 간격(기본 0.8s) | 공격력(기본 25) |
|---|---|---|---|
| 0% | 0.00 | **공격 불가** | **공격 불가** |
| 5% | 0.50 | 1.60s | 12.5 |
| 10% | 0.60 | 1.33s | 15.0 |
| 20% | 0.80 | 1.00s | 20.0 |
| 30% 이상 | 1.00 | 0.80s | 25.0 |

> **왜 이 형태인가**: (1) 정상 운영 구간(30% 이상)에서는 계수가 1로 평탄해, 재고가 조금 출렁여도 전투감이 흔들리지 않는다. (2) 30% 아래로 떨어지면 즉시 체감되는 성능 저하가 시작돼 **"보급이 늦었다"는 경고**로 작동한다. (3) 0에서만 완전 정지라, 실수 한 번이 곧바로 패배로 직결되지는 않는다. floor 0.4가 그 유예 구간이다. safe와 floor 모두 치트 메뉴에서 실시간 조정 가능하다.

## 3. 맵 구조 — 원형 방어선

맵의 골격은 **하나의 큰 원(방어선)**이다. 원의 중심은 화면 아래쪽 바깥에 있어, 화면에는 완만한 **호(arc)**만 보인다.

```
        ↓ 침공        ↓ 침공        ↓ 침공          ← 적은 바깥에서 중심을 향해 밀고 들어온다
   ───🏰────────────🏰───────────🏰───────         ← 방어선. 침공 루트와의 접점에 요새가 선다
      ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·          ← (점선) 건설 한계선
          📦 창고      🌾 농경지                     ← 아군 영토(안쪽). 물류망은 전부 여기에
              🐴 마굿간      ⚔️ 대장간
```

| 구분 | 규칙 |
|---|---|
| 방어선 | 반지름 900의 원. 중심은 화면 아래 바깥(640, 1150) |
| 요새 | **방어선 위**, 침공 루트와 원이 만나는 접점에 자동 생성 |
| 적 | 방어선 바깥 170 거리에서 출현해 자기 요새를 향해 직진 |
| 생산지 | 항상 방어선 **안쪽**에 자동 생성 |
| 창고·마굿간 | 방어선 안쪽(건설 한계선 = 방어선에서 55 안쪽) 내 **원하는 위치** |

> **설계 의도**: 요새가 원 위에 흩어져 있고 물류 자원은 안쪽에 모여 있으므로, 플레이어의 물류망은 자연히 **중심부 허브에서 각 요새로 뻗어 나가는 방사형**이 된다. 전선이 늘어날수록 허브에서 더 먼 곳까지 선을 뻗어야 하고, 이것이 후반 난이도의 핵심이다. 창고를 중심 가까이 둘지 요새 가까이 둘지가 매 판의 주요 결정이 된다.

## 4. 오브젝트 정의

### 4.1 자동 생성 (플레이어가 위치를 못 고름)

**생산지** — 지정 시간마다 재화를 생산하고, 최대 적재량에 도달하면 **생산이 멈춘다**(마차가 비워줘야 재개).

| 종류 | 생산품 | 생산 속도 | 최대 적재량 | 상하차 속도 |
|---|---|---|---|---|
| 🌾 농경지 | 식량 | 5s / 1개 | 10 | 0.3s / 물류1 |
| ⚔️ 대장간 | 무기 | 10s / 1개 | 5 | 0.3s / 물류1 |
| 🪨 채석장 | 석재 | 10s / 1개 | 5 | 0.3s / 물류1 |

> 2웨이브마다 랜덤한 생산지 1곳이 추가로 발견된다.

**요새** — 적 침공 루트가 정해지면 **그 루트와 방어선이 만나는 접점**에 자동 생성된다. 생성 시 **모든 자원이 0**이며, 적이 오기까지 약 25초의 유예가 있다. 하나라도 성벽이 0이 되면 게임 오버.

| 체력 | 공격력 | 공격 간격 | 사거리 | 식량 소모 | 무기 소모 | 석재당 회복 |
|---|---|---|---|---|---|---|
| 5000 | 25 | 0.8s | 210 | 10s/1 (상시) | 8s/1 (전투 중) | 100 |

- 최대 적재량: 식량 40 / 무기 30 / 석재 20
- 석재는 성벽이 98% 미만이면 **자동 소모**되어 1개당 100 회복
- 3웨이브마다 새 전선(요새)이 최대 4기까지 추가된다

**요새 강화 (코인)** — 웨이브마다 적이 늘어나는데 요새 성능은 고정이므로, 강화 없이는 반드시 뚫린다.

| 항목 | 값 |
|---|---|
| 비용 | `100 x 1.45^현재단계` (100 → 145 → 210 → 305 → …) |
| 효과 | 단계당 공격력 +30%, 공격속도 +12% |
| 최대 | 6단계 (공격력 x2.8, 공속 x1.72) |

### 4.2 플레이어 지정 생성

**창고** — 자원을 종류 무관하게 모아두는 환승역. 여러 노선이 만날 수 있고, 마차가 도착하면 **싣고 온 것을 전부 내린 뒤 그 노선의 요새가 필요한 만큼만 다시 싣는다.**

| 종류 | 최대 적재량 | 상하차 속도 | 신축 비용 | 확장 비용 |
|---|---|---|---|---|
| 소형 창고 | 20 | 0.3s / 물류1 | 허가권 ×1 | — |
| 중형 창고 | 40 | 0.2s / 물류1 | 허가권 ×1 + 🪙50 | 🪙50 |
| 대형 창고 | 60 | 0.1s / 물류1 | 허가권 ×1 + 🪙100 | 🪙100 |

**마차 증차 (코인)** — 같은 노선에 마차를 더 투입해 왕복 간격을 줄인다. N번째 추가 마차 비용 `80 x N`, 노선당 최대 4대.

**마굿간** — 비용: 마굿간 허가권 ×1. **노선에 마굿간이 최소 1개 있어야 마차가 다닌다.** 마차 종류와 짐칸 편성을 여기서 지정하며, **변경된 편성은 마차가 이 마굿간을 지나갈 때 적용된다.**

### 4.3 길 (노선)
- 건물을 순서대로 클릭해 노선을 잇는다. 시작 건물을 다시 클릭하면 **순환선**이 된다.
- 순환선이 아니면 마차가 종점에서 **왕복**한다.
- 노선이 달라도 창고를 통해 서로 자원을 교환할 수 있다 (호선 개념).
- 노선당 마차 1대가 자동 배치된다.

## 6. 밸런스 검증 결과

### 6.1 실제 플레이 테스트로 발견하고 고친 것

브라우저에서 실제로 조작해 플레이한 결과, 전략과 무관하게 5웨이브에서 전멸하는 구조적 결함들이 드러났다. 아래는 그 원인과 조치다.

| 발견한 문제 | 원인 | 조치 |
|---|---|---|
| 마차가 복귀 시 엉뚱한 노드에서 상하차 | 왕복 로직의 off-by-one — 후진 중 도착 판정이 한 칸 어긋남 | 전진/후진 도착 판정을 분리해 수정 |
| 1웨이브를 어떤 전략으로도 온전히 못 막음 | 준비 30초 동안 전체 생산량이 12개뿐인데 요새는 70개가 필요 | 생산지는 재고가 가득 찬 상태로 시작 + 최초 준비 60초 |
| 새 전선이 열리면 반드시 함락 | 자원 0으로 출현해 30초 안에 보급 불가, 공격 불능 상태로 파괴 | 수비대 초기 보급 50% + 새 전선 준비 시간 60초 + 전선 뒤 생산지 3곳 동반 생성 |
| 어떤 전략도 5웨이브를 못 넘김 | 몬스터는 매 웨이브 증가하는데 요새 성능은 고정 (성장 축 부재) | **요새 강화** 추가 — 코인의 핵심 사용처 |
| 코인이 700 넘게 남아돎 | 쓸 곳이 창고 확장뿐 | 요새 강화 + 마차 증차 추가, 코인 수입 상향 |

### 6.2 전략 비교 (5개 시드 평균 도달 웨이브)

동일 조건에서 전략만 바꿔 자동 플레이한 결과다. 수치가 벌어질수록 "정답이 하나로 강제되지 않는다"는 뜻이다.

| 전략 | 평균 도달 웨이브 |
|---|---|
| 식량·무기 최단선 + **요새 강화** | **8.2** |
| 식량·무기 최단선 + 마차 증차 | 6.4 |
| 식량·무기 최단선 (석재 무시) | 6.0 |
| 전선별 전용 노선 + 강화 + 증차 | 6.4 |
| 전 자원 + 강화 + 증차 | 5.0 |
| 전 자원 순환선 1개 | 3.8 |
| 전 자원 왕복선 1개 | 3.0 |
| 중앙 허브 + 순환선 | 2.8 |

**아직 남은 문제**: 요새 강화가 다른 모든 축을 압도한다(8.2 vs 6.4). 반대로 창고·허브·석재를 쓰는 전략이 오히려 손해다 — 먼 채석장을 노선에 넣으면 식량·무기 처리량이 희석되어 손해가 이득보다 크다. 창고의 환승 기능이 제값을 하려면 **자원별 수요 분리**나 **원거리 노선 패널티 완화**가 더 필요하다.

### 6.3 시뮬레이션 실측치

| 조건 | 결과 |
|---|---|
| 보급 전무 (노선 미구축) | 약 105초, 웨이브 1에서 패배 |
| 식량·무기만 만땅, 석재 0 | 웨이브 6 전후 패배 — **석재/성벽 수리가 생존의 핵심 축** |
| 식량·무기·석재 전부 만땅 | 웨이브 18+ 무피해 — 물류가 완벽하면 전투는 자동으로 풀린다 |
| 요새 1기 + 전용 순환 노선 1개 | 웨이브 1~4 동안 성벽 45~75%에서 안정. 무기 재고가 0 부근에 머무르며 병목으로 작동 |
| 위와 동일하되 노선을 확장하지 않음 | **웨이브 4에서 패배** — 3웨이브에 생성된 두 번째 요새가 보급을 못 받고 함락. 1번 요새는 63%로 멀쩡했다 |

**설계상 의도한 병목 순서**: 초반은 무기(대장간 0.1/s가 요새 소모 0.125/s에 못 미침) → 중반은 요새 증가에 따른 노선 처리량 → 후반은 창고 적재량과 마차 회전율. 각 단계마다 코인/허가권 사용처가 달라지도록 설계했다.

## 9. 장기 로드맵 (미구현)

원본 `장기 로드맵` 시트 기준, MVP 이후 확장 방향:

- **2차 가공**: 철광산 → 대장간 → 무기. 생산 체인이 길어지며 창고의 환승 역할이 중요해진다.
- **장군**: 요새에 배치해 특수 능력 부여 (예: 보급관 — 식량 소모량 감소).
- **군주**: 런 전체에 걸린 변형 규칙 (예: 성질급한 제이슨 — 마차 속도 증가, 장군 등장률 감소).
- **요새 강화**: 대포(화약 소모, 범위 공격) / 독화살(독 소모, 지속 피해) + 화약소·연금소 생산지 추가.
